# 上位机功能与接口设计

版本：0.1。日期：2026-09-07。

本文区分已实现的模拟功能与拟开发的实机功能，不是已确认的控制协议或验收标准。未修改项目原有合同、技术方案或官方文件。

## 1. 软件与控制职责

Windows PC：配方管理、状态显示、数据记录、测试指标计算、历史查询及报告。

底层控制器：拟采用 STM32H755；负责同步采集、运动时序、加载闭环及设备状态上报，具体接口以硬件最终选型为准。实际急停、驱动器 STO 与硬限位由硬件保护体系落实，上位机不承担实时安全功能。

当前程序只调用内置模拟器。设备与标定页面为接入状态说明，尚无真实标定操作。

## 2. 四种模式

| 模式 | 实机流程设计 | 当前模拟实现 | 实机接入前需确认 |
| --- | --- | --- | --- |
| 传动效率 | 检查夹持及零位、加载、运行至稳态、采样、卸载及停机 | 稳态驱动功率比、双向往复模拟 | 扭矩及力方向、传动边界、稳态判据、负载与速度范围 |
| 轴向游隙 | 低速运动及双向加载，识别两侧稳定接触状态并计算相对位移变化 | 两方向理论位移与实际位移的残差差值 | 测量基准、角度同步、加载值、B+/B-定义、弹性修正 |
| 轴向刚度 | 保持角位置，分级加载及卸载，记录力与相对位移并拟合 | 10级加载/卸载模拟及整体斜率拟合 | 位移测点、刚度分段、夹具与台架柔度、加载卸载分别拟合 |
| 往复疲劳 | 按速度、行程、载荷往复运行，周期检查及停机 | 往返计一次，达到目标循环数停止 | 检查间隔、终止条件、断电续测、长期存储与真实失效判据 |

当前游隙模式没有测量系统弹性修正，刚度结果未扣除台架影响。疲劳循环数不等于疲劳寿命。不得把上述模拟计算称为已完成计量验证的测量算法。

## 3. 数据字段

| 字段 | 单位 | 说明 |
| --- | --- | --- |
| Sequence / Time | 序号 / s | 当前为模拟器序号和相对时间；实机应采用控制器时钟 |
| Force | N | 带符号的轴向力 |
| Torque | N·m | 带符号的输入轴转矩 |
| Rpm / Angle | rpm / rad | 转速及连续角度，实机需处理编码器回绕 |
| Position / Velocity | mm / mm/s | 位移及线速度；实机需确认位移基准及速度来源 |
| Cycles | 次 | 完整往返的累计次数 |
| Valid / Steady | 布尔值 | 采样有效性及稳态标志，当前由模拟器给出 |
| Source | 数据来源 | 当前固定 SIMULATED；实机记录必须与模拟记录明确区分 |

以上是逻辑通道，不代表相同数量的独立传感器；角度与转速可来自同一编码器，速度可以来自位移差分。实际传感器数量、独立通道与同步精度需与最终机械及电气方案逐项核定。

## 4. 通信设计草案

拟优先评估有线以太网 TCP；当前未实现 TCP、串口或实机适配器，不自动连接任何地址。接口冻结前不启用运动输出。

| 方向 | 消息 | 主要字段 |
| --- | --- | --- |
| PC到控制器 | 握手与状态查询 | 协议版本、设备编号、固件版本、会话编号 |
| PC到控制器 | 配方下发 | 命令编号、模式、导程、速度、力、行程、时长、循环数、配方版本 |
| PC到控制器 | 启动/暂停/继续/停止/复位 | 命令编号、运行编号、预期设备状态 |
| 控制器到PC | 应答 | 原命令编号、成功/拒绝、原因、实际状态 |
| 控制器到PC | 批量采样 | 帧序号、首样本时间、采样周期、通道定义、原始值、状态标志 |
| 控制器到PC | 报警与事件 | 报警编号、发生/解除时间、锁存状态、停机原因 |
| 双向 | 心跳 | 会话编号、设备时间、运行编号、当前状态 |

帧编码、字节序、长度上限、CRC形式、命令超时、心跳周期与采样率均待协议冻结，不在此伪造既定值。协议需处理 TCP 分包/合包、非法长度、重复命令、丢失序号、设备重启及版本不兼容。CRC不替代权限控制。

为便于硬件接入前联调，界面已提供独立的数据包调试窗口：可监听端口或连接设备，显示原始十六进制字节流，并按外置 JSON 字段定义（偏移、类型、字节序、缩放、单位）解析显示，支持本机回环发送测试帧验证解析。内置布局为草案示例，**不代表协议已冻结**；协议冻结后替换布局文件即可。该窗口处理 TCP 分包/合包与同步头扫描，但不替代协议本身的 CRC 与命令合法性校验。

软件实机架构拟拆分为设备适配层、后台采集队列、独立文件写入、指标计算和界面刷新。采样率与刷新率分别配置，不以当前20 Hz模拟刷新作为硬件采样指标。

## 5. 异常与安全

- 运动命令成功与否以控制器应答及状态反馈为准，按钮点击不代表动作完成。
- 启动前核查急停、限位、驱动器、传感器有效性、零位、夹持及配方范围。
- 断线后禁止上位机自动恢复运动。底层执行经风险评估确定的保护动作，重新连接后人工确认状态。
- 磁盘异常、队列溢出、时钟异常及丢包应留痕，并明确标记受影响的数据区间。
- 原始数据与计算结果分别保存，绑定样件、设备、配方、标定及算法版本。
- 长期疲劳运行采用流式存储及有界缓存，完成异常断电和连续运行测试后再开放无人值守运行。

## 6. 后续开发安排

以下为开发建议，非合同承诺。时间以接口资料齐备并可使用样机的日期T0为起点。

| 阶段 | 建议时间 | 交付内容 | 前置条件 |
| --- | --- | --- | --- |
| 需求及协议冻结 | T0后第1周 | 量程、通道、流程、时序、错误码、验收用例 | 机械、电气、控制负责人共同确认 |
| 通信与采集 | 第2-3周 | 设备适配、采集队列、标定、异常处理 | 控制器固件、传感器及联调环境 |
| 测试算法联调 | 第4-5周 | 四模式流程、实测算法、原始数据回溯 | 基准件、标定数据、测试边界 |
| 稳定性及交付 | 第6周起 | 安装包、文档、异常与长时测试报告 | 已冻结验收标准及现场设备 |

长期疲劳验证的日历周期取决于实际循环次数和工况，不包含在上述软件开发周数内。三维可视化及寿命预测另立任务，不混入本次基础上位机的完成范围。
