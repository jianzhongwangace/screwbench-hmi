# 上位机 ↔ STM32 通信协议 v0.1（草案 · 待双方确认）

适用范围：丝杠螺母综合测试台，**数据上行方向**（STM32 → 上位机）的采样帧格式。
对应上位机：`ScrewBench` 数据包调试窗口（`src/Desktop/PacketInspectorWindow.cs`），布局文件 `examples/packet-layout-draft.json`。

> 本文件为草案，尚未冻结。任何变更需双方确认，并同步更新布局 JSON（上位机无需改代码）。
> 命令下行方向（上位机 → STM32）见第 9 节；**本版范围：仅上行接收**，不影响本版联调。

---

## 1. 连接方式

| 项目 | 约定 |
|---|---|
| 传输层 | TCP/IP over Ethernet |
| 默认角色 | **上位机 = TCP 服务端**，监听端口 `9000`；STM32 = 客户端，主动连接 |
| 备用角色 | STM32 做服务端时，上位机调试窗口切「TCP 客户端」，填设备 IP + 端口 |
| 建连后 | STM32 立即按采样周期连续发送采样帧 |
| 断线 | STM32 检测发送失败后重连（上位机客户端模式自带 3 s 重连；服务端模式由 STM32 负责） |
| IP / 端口 | 可配置，但**帧格式不随 IP 变化** |

---

## 2. 通用规则

1. **字节序：小端（Little Endian）**——多字节字段低字节在前。
2. 有符号整型为二进制补码，无符号为原码。
3. 帧长固定 **32 字节**（本版）。
4. 时间戳单位毫秒，字段为 `uint32`。
5. 工程量换算：**工程量 = 原始码 × scale**。
6. **禁止在数据流中插入 ASCII 调试文本**（如 printf 日志），否则上位机会当作垃圾丢弃，并可能导致帧同步错位。

---

## 3. 帧结构（32 字节）

| 偏移 | 长度 | 字段 | 类型 | scale | 单位 | 说明 |
|---:|---:|---|---|---:|---|---|
| 0 | 2 | `sync` | uint16 | — | — | 固定 `0xAA55`，字节顺序 **AA 在前、55 在后** |
| 2 | 2 | `length` | uint16 | — | 字节 | 整帧字节数，**含同步头与本字段**；本版固定 `32`（`0x0020`） |
| 4 | 4 | `timestamp` | uint32 | 0.001 | s | 控制器毫秒计时（原始值为 ms） |
| 8 | 4 | `sample_seq` | uint32 | 1 | — | 采样序号，从 1 递增，不得回退 |
| 12 | 2 | `torque` | int16 | 0.01 | N·m | 输入轴扭矩，带符号 |
| 14 | 2 | `force` | int16 | 0.1 | N | 轴向力，带符号 |
| 16 | 4 | `position` | int32 | 0.001 | mm | 光栅位移 |
| 20 | 2 | `rpm` | int16 | 1 | rpm | 转速，带符号（正负表方向） |
| 22 | 4 | `angle` | uint32 | 0.0001 | rad | 连续展开角（v0.1 暂定无符号，见第 16 节待确认） |
| 26 | 2 | `status` | uint16 | 1 | 位域 | 设备状态位，见第 5 节 |
| 28 | 1 | `quality` | uint8 | 1 | 枚举 | 数据质量，见第 6 节 |
| 29 | 1 | `flags` | uint8 | 1 | 位域 | 方向 / 工况标志，见第 7 节 |
| 30 | 2 | `crc16` | uint16 | — | — | CRC16/CCITT-FALSE，**覆盖范围 0..29 共 30 字节** |

## 3.1 文本帧（变长，联调 / 调试专用）

用于联调第一步：先发一段纯文本验证链路通不通，再上采样帧。同步头不同，上位机自动区分两种帧。

| 偏移 | 长度 | 字段 | 说明 |
|---:|---:|---|---|
| 0 | 2 | `sync` | 固定 `0xAA54`（字节顺序 **AA 在前、54 在后**） |
| 2 | 2 | `length` | uint16，整帧字节数（含同步头、本字段、CRC），**最小 6** |
| 4 | N | `text` | ASCII 字符串，N = length − 6，**不含结尾 NUL** |
| 4+N | 2 | `crc16` | uint16，CRC16/CCITT-FALSE，**覆盖前 length−2 字节** |

**示例：发送 `lab202`**（6 字节文本 → 帧长 12）

```
AA 54 0C 00 6C 61 62 32 30 32 33 C2
```

| 字节 | 含义 |
|---|---|
| `AA 54` | 文本帧同步头 |
| `0C 00` | length = 12 |
| `6C 61 62 32 30 32` | ASCII `l a b 2 0 2` |
| `33 C2` | CRC = 0xC233（小端存储） |

参考实现（C）：

```c
void send_text(int sock, const char *text)
{
    uint16_t n = (uint16_t)strlen(text);
    uint16_t length = (uint16_t)(4 + n + 2);
    uint8_t frame[128];
    frame[0] = 0xAA; frame[1] = 0x54;
    frame[2] = (uint8_t)(length & 0xFF);
    frame[3] = (uint8_t)(length >> 8);
    memcpy(&frame[4], text, n);
    uint16_t crc = crc16_ccitt_false(frame, (uint16_t)(length - 2));
    frame[length - 2] = (uint8_t)(crc & 0xFF);
    frame[length - 1] = (uint8_t)(crc >> 8);
    send(sock, frame, length, 0);
}
/* 调用：send_text(sock, "lab202"); */
```

**上位机显示**：收到文本帧后，左侧显示原始十六进制，右侧解析表显示 `text` 字段内容（`lab202`）与 CRC 校验结果。

## 4. 量程与分辨率（打包前必须校核）

| 字段 | 分辨率 | int16 / int32 可表达上限 |
|---|---|---|
| `torque` | 0.01 N·m | ±327.67 N·m |
| `force` | 0.1 N | ±3276.7 N |
| `position` | 0.001 mm | ±2147483.647 mm |
| `rpm` | 1 rpm | ±32767 rpm |
| `angle` | 0.0001 rad | 0 ~ 429496.7295 rad |

**要求**：各通道 scale 必须由实际传感器额定值与峰值工况反算确定，不能照搬本表。打包前若原始码超出类型范围，必须**钳位并把 `quality` 置为 3（OutOfRange）**，不允许静默溢出回绕。

## 5. `status` 位域（草案建议）

| 位 | 含义 | 位 | 含义 |
|---:|---|---:|---|
| 0 | 急停触发 | 8 | 软限位 |
| 1 | 正限位 | 9 | 力跟踪异常 |
| 2 | 负限位 | 10 | 无法换向 |
| 3 | 轴向力超限 | 11 | 环形缓冲将溢出（原始高速数据可能丢失） |
| 4 | 扭矩超限 | 12 | 试验运行中 |
| 5 | 传感器断线 / 饱和 | 13 | 暂停中 |
| 6 | 通信异常（Modbus / 驱动器） | 14 | 故障锁存 |
| 7 | 驱动器故障 | 15 | 保留 |

## 6. `quality` 枚举

| 值 | 含义 | 上位机处理方式 |
|---:|---|---|
| 0 | Valid | 参与指标计算与模型更新 |
| 1 | Transient | 加减速 / 换向瞬态，不参与稳态统计 |

| 3 | OutOfRange | 超量程，剔除并报警 |
| 4 | ManualOverride | 人工干预，需保存操作人、时间与备注 |

## 8. CRC16 算法

- 算法：**CRC-16/CCITT-FALSE**
- 多项式 `0x1021`，初值 `0xFFFF`，输入/输出**不反射**，输出**不异或**
- 计算范围：帧的 **前 30 字节**（偏移 0 至 29），结果以小端写入偏移 30

```c
uint16_t crc16_ccitt_false(const uint8_t *data, uint16_t len)
{
    uint16_t crc = 0xFFFF;
    for (uint16_t i = 0; i < len; i++) {
        crc ^= (uint16_t)data[i] << 8;
        for (uint8_t b = 0; b < 8; b++) {
            crc = (crc & 0x8000) ? (uint16_t)((crc << 1) ^ 0x1021)
                                 : (uint16_t)(crc << 1);
        }
    }
    return crc;
}
```

## 10. 帧同步与 TCP 分包 / 合包

TCP 是字节流，没有消息边界。约定：

1. **STM32 每帧一次 `send()` 发满 32 字节**，不要拆成多次小包；允许一次 `send` 多帧（合包）。
2. 上位机处理逻辑：扫描 `0xAA55` 同步头 → 读 `length` → 取满一整帧 → 校验 CRC → 解析；缓冲区不足时等待下一批数据。
3. 收到非法长度（`<32` 或 `>1024`）时，上位机丢弃该段并重新扫描同步头。
4. 上位机统计**序号跳变**次数（用于发现丢包 / 乱序）。

---

## 11. 序号与时间戳

- `sample_seq` 每发一帧 +1，从 1 开始；设备重启后从 1 重新计数（上位机据此判定重连后的新任务）。
- 不允许用「设定转速 × 运行时间」推算循环数——循环计数必须由实际位移 / 载荷状态机确认后累计。
- `timestamp` 为 `uint32` 毫秒，回绕周期约 49.7 天；长时间疲劳试验的回绕处理见第 16 节待确认。

## 12. 示例帧（可直接用于比对）

```
AA 55 20 00 87 D6 12 00 01 00 00 00 E2 04 48 26 19 00 00 00 2C 01 8B 18 00 00 00 00 00 00 8B 17
```

逐字段解释：

| 字节 | 字段 | 原始码（小端） | 工程量 |
|---|---|---:|---|
| `AA 55` | sync | — | 同步头 |
| `20 00` | length | 32 | 32 字节 |
| `87 D6 12 00` | timestamp | 1234567 ms | **1234.567 s** |
| `01 00 00 00` | sample_seq | 1 | 第 1 帧 |
| `E2 04` | torque | 1250 | **12.50 N·m** |
| `48 26` | force | 9800 | **980.0 N** |
| `19 00 00 00` | position | 25 | **0.025 mm** |
| `2C 01` | rpm | 300 | **300 rpm** |
| `8B 18 00 00` | angle | 6283 | **0.6283 rad** |
| `00 00` | status | 0 | 无故障 |
| `00` | quality | 0 | Valid |
| `00` | flags | 0 | — |
| `8B 17` | crc16 | 0x178B（小端存储） | 校验值 |

**CRC 验证**：对前 30 字节计算 CRC16/CCITT-FALSE = `0x178B`，与帧内一致。

## 13. 参考实现（C，可直接用）

```c
#pragma pack(push, 1)
typedef struct {
    uint8_t  sync[2];      /* AA 55 */
    uint16_t length;       /* 32 */
    uint32_t timestamp;    /* ms */
    uint32_t sample_seq;   /* 从 1 递增 */
    int16_t  torque;       /* 0.01 N·m */
    int16_t  force;        /* 0.1 N */
    int32_t  position;     /* 0.001 mm */
    int16_t  rpm;          /* rpm */
    uint32_t angle;        /* 0.0001 rad */
    uint16_t status;       /* 位域 */
    uint8_t  quality;      /* 枚举 */
    uint8_t  flags;        /* 位域 */
    uint16_t crc16;        /* 覆盖前 30 字节 */
} sample_frame_t;          /* sizeof == 32 */
#pragma pack(pop)

void build_frame(sample_frame_t *f, uint32_t ts_ms, uint32_t seq,
                 float torque_nm, float force_n, float pos_mm,
                 int16_t rpm, float angle_rad,
                 uint16_t status, uint8_t quality, uint8_t flags)
{
    f->sync[0]  = 0xAA;
    f->sync[1]  = 0x55;
    f->length   = 32;                                        /* 小端 MCU 直接赋值；大端 MCU 需字节交换 */
    f->timestamp = ts_ms;
    f->sample_seq = seq;
    f->torque   = (int16_t)lroundf(torque_nm / 0.01f);
    f->force    = (int16_t)lroundf(force_n   / 0.1f);
    f->position = (int32_t)lroundf(pos_mm    / 0.001f);
    f->rpm      = rpm;
    f->angle    = (uint32_t)lroundf(angle_rad / 0.0001f);
    f->status   = status;
    f->quality  = quality;
    f->flags    = flags;
    f->crc16    = 0;
    f->crc16    = crc16_ccitt_false((const uint8_t *)f, 30); /* 只算前 30 字节 */
}

/* 发送：整帧一次发出，不要分包 */
/* send(sock, (const uint8_t *)frame, 32, 0); */
```

注意：结构体打包前必须做量程钳位检查（见第 4 节）；`sync` 用 `uint8_t[2]` 而非 `uint16_t`，避免字节序与对齐问题。

## 14. 联调步骤

0. **联调第一步（发文本帧）**：STM32 调用 `send_text(sock, "lab202")`，上位机「数据包调试」窗口应显示原始 hex `AA 54 0C 00 6C 61 62 32 30 32 33 C2`、右侧解析出 `text = lab202`、CRC = OK。这一步通了，链路就通了。
1. **再离线比对**：STM32 打包上面第 12 节的示例参数，用网络调试助手发到 PC `9000`，抓包确认字节序列与示例完全一致。
2. **接上位机**：打开 ScrewBench → 点「数据包调试」→ 端口 9000 → 启动 → STM32 连接并发送。
3. **看四个指标**：帧数递增、**CRC 错 = 0**、**序号跳变 = 0**、右侧解析出的工程量与 STM32 侧一致。
4. **无硬件自测**：点窗口内「发送测试帧」（采样帧）或填文本后点「发送文本帧」，本机回环生成一帧并解析，验证上位机链路本身没问题。

## 附录 B：字节流不符时的排错对照

| 现象 | 原因 | 修法 |
|---|---|---|
| 第 3–4 字节是 `00 20` 而不是 `20 00` | 字节序反了（大端 / 误用 `htons`） | 全长小端逐字节写，不要用网络字节序函数 |
| 帧长不是 32 字节 | 结构体未加 `#pragma pack(1)`，编译器插入填充 | 加 pack，或用手工逐字段 memcpy 打包 |
| 除 CRC 外全部一致 | CRC 计算范围错（算了 32 字节，或把 CRC 字段自身也算进去） | 只对**前 30 字节**计算 |
| 前几字节对、后面全乱 | 字段顺序或类型长度不符（如 position 用了 int16） | 逐字段核对第 3 节偏移表 |
| 上位机能解析但 CRC 错 | 同上，或 CRC 初值/多项式不对 | 确认 init=0xFFFF、poly=0x1021、非反射、输出不异或 |
| 上位机帧数不涨 | 未整帧发送 / 中途插入了调试打印 | 一次 `send()` 发满 32 字节，禁止在数据流里打印 ASCII |
